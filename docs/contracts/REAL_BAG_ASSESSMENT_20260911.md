## 발견 사항과 영향

### 높음: 영상·RCOut·DVL의 서로 다른 시계

컬러 영상의 기록 시각−헤더 시각은 최소 1.1843초, 중앙값 1.5069초, p95 2.2048초, 최대 11.6553초다. 이미지 기록 간 최대 공백은 8.0439초다. 헤더 401개와 픽셀 해시 401개는 각각 고유하다. 이는 중복 프레임 문제가 아니라 낮고 불규칙한 기록률 및 시각 정렬 문제다. 카메라 원래 발행률이나 네트워크 손실률은 이 bag만으로 확정할 수 없다.

RCOut 기록−헤더 중앙값은 4294.9685초다. 2^32 마이크로초(4294.967296초)와 거의 일치해 32비트 시간 wrap/변환 문제를 의심할 수 있지만, 원인 확정에는 당시 MAVROS/FCU 버전과 timesync 분석이 필요하다. `/rosout`에도 `TM: Wrong FCU time.` 경고 3개가 있다. 임의로 상수를 빼서 학습 데이터를 생성하지 않았다.

DVL 장치 time_of_validity와 호스트 헤더의 절대 시각은 약 58,314,121초 차이 난다. 장치 내부 transmission−validity 차이는 중앙값 0.1034초, 범위 0.0794~0.1248초다. 호스트 헤더가 캡처 시각이라는 근거로 쓸 수 없다. 이 장치 내 차이도 전체 end-to-end 센서 지연과 다르다.

### 높음: 현재 freshness 규칙을 만족하지 못하는 입력

기록 시작 2초 뒤부터 끝까지 0.1초 간격 1,450개 시점에서, 그 시점까지 기록된 최신 메시지의 헤더를 사용해 age∈[0,0.25] 비율을 계산했다.

| 입력 | 유효 age 비율 |
|---|---:|
| 컬러 | 0.00% |
| IMU | 99.66% |
| DVL twist | 99.17% |
| depth pose | 39.24% |

격자 위상에 따라 depth 비율은 달라진다. 핵심은 2 Hz 수심을 10 Hz에서 0.25초 이하로 항상 신선하게 받을 수 없다는 점이다. 카메라를 늦은 헤더 그대로 replay하면 실패하며 수신 시각으로 덮으면 관측·행동 의미가 바뀐다. 실물 프로필의 센서별 age 기준이나 상태 추정을 설계할 근거는 되지만, 단순히 제한을 완화해 학습 품질을 보장할 수는 없다.

### 중간~높음: IMU 가속도 크기 확인 필요

quaternion norm은 1±수치 오차로 정상이다. 무장 전 저속 후보 구간에서 가속도 norm 중앙값 8.8919 m/s², disarm 15초 이후 구간에서 8.9001 m/s²다. 후자 DVL 속력 중앙값은 0.00445 m/s, p95 0.01007 m/s라 비교적 정적인 후보다. 이 가속도를 중력 포함 specific-force로 해석하면 통상 중력 크기 약 9.81 m/s²보다 약 9% 작다. 큰 비정상 후보지만 scale/bias/원본 단위/센서 설정 중 원인을 이 기록만으로 확정할 수 없다. 단순 자세 회전으로 norm 차이는 설명되지 않는다. 현재 시뮬 가속도를 8.9로 맞추지 않았다. 실물 가속도계 6면 정지 시험과 FCU 보정 파라미터가 우선이다.

bag에는 base_link와 카메라를 연결하는 static TF가 확인되지 않았고 RealSense 내부 변환은 존재한다. 당시 TF도 설정 값이지 실측 증명은 아니다. 과거 launch 좌표를 현재 CAD 모델에 그대로 덮어쓰면 안 된다.

### 확인됨: invalid DVL이 실제로 존재

15/1,378개(1.089%)가 velocity_valid=false이고 altitude에는 -1이 나타난다. raw→twist matching은 모두 같은 헤더/벡터를 보존하며 invalid 필터 경고도 있다. 현재 collector의 invalid 처리·stale twist 방지 회귀 시험을 확장할 실물 사례가 확보됐다. 하드웨어 validity가 항상 1인 시뮬 정지 자료만으로 시험하는 것보다 유용하다.

## 활용 구간과 가능한 검증

상대 시간은 bag 최초 기록 기준이며 State 도착 지연이 있어 정확한 실제 전환 시각은 아니다.

- 0~18.10초: 비무장 ALT_HOLD, 저속 후보. IMU/DVL 정지 특성 참고.
- 18.10~72.27초: 무장 ALT_HOLD. 요청 RC와 DVL 속도·회전 응답을 개략 비교 가능.
- 72.27~73.10초: 무장 MANUAL 전환. 모드 전환·episode 분리 사례.
- 73.10초 이후: 비무장 MANUAL. 잔류 운동 후 88.10초 이후를 정지 후보로 별도 분석.

무장 구간 DVL 속력 중앙값 0.2566 m/s, p95 0.4289 m/s다. 정지뿐인 자료가 아니다. 그러나 ALT_HOLD 제어기·벽·테더·접촉·조종축 혼합 때문에 명령→속도 관계를 순수 추진기/항력 계수로 식별하기 어렵다. RCOut은 2 Hz이고 시각 문제도 있어 빠른 지연 추정에 불충분하다.

가능: 토픽/type/frame 계약, DVL invalid와 bridge 동작, 시계 이상 탐지, 실제 기록률과 freshness 평가, 저속 구간 노이즈 후보, 명령/운동의 개략 범위, 해당 RealSense 수중 영상의 정성 비교.

조건부: 당시 좌표계·모드·추진기 설정을 확인한 뒤 surge/yaw 응답 경향 비교, 카메라 시간 문제 해결 후 관측/행동 사후 정렬. 영상 motion과 IMU 교차 비교로 시차 후보는 추정 가능하나 고유한 절대 시각 해를 보장하지 않는다.

불가: 질량·관성·무게중심·순부력·절대 추력·항력·자석 15 N·줄 물성 확정, 현재 IMX219 전방/손 카메라 보정, 현재 작업 성공률/실물 전이 성능 입증, 현재 VLA의 두 카메라 10 Hz 작업 시연 직접 생성. 낮은 이미지율을 중복/보간해 실제 10 Hz 관측으로 만들 수 없다.
