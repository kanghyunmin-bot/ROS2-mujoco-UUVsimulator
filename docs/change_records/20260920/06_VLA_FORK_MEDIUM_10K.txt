포크 레퍼런스 기반 중간 강조 추가 10,000스텝
작성일: 2026-09-20

사용자 승인: 참조 이미지와 다음 학습 메모를 활용해 중간 강조 만개 학습,
진행상황 HTML 열기. 만개는 추가 10,000 optimizer step으로 해석하여 안내.

실험 폴더: outputs/vla-fork-medium-10k-20260920/
진행 화면: http://127.0.0.1:8883/ (localhost 읽기 전용, 3초 갱신)
시작 모델: outputs/vla-sixhour-20260920/weight-2/model/checkpoint-40000
중간 강조 분기 중 기존 오프라인 MSE 최소 모델(0.0834077).
optimizer/scheduler는 새로 시작, lr 2e-5, batch 1, seed 42,
projector + diffusion 학습, 시각/언어 백본 고정, bf16, CAP=0.
5,000 / 10,000스텝 저장 후 기존 10 validation episode의 40관측 자동 평가.
실제 운전은 실행하지 않음. 기존 야간 자동화는 재개하지 않음.

기존 원본과 모델 및 미커밋 변경 보존. 실험 코드는 별도 outputs 안에 저장.
prepare.py: 학습 40 episode 원본 samples.npz 해시 확인. 참조 RGB 20장 해시 기록.
기존 중앙1.15 / 크기1.4 / 검토 손카메라근접2 강조 유지.
잘린 노란 영역도 '보임' 판정에 사용. 중앙 판정의 잘림 제외는 유지.
전방 근접 하한: 참조 전방 최소 노란 면적의 0.5배 = 0.02253038.
기존 검토 구간 AND 전방 근접 AND 손카메라 노란 면적>=0.001,
3프레임 지속 시 근접 후보 1.4배: 408프레임.
손카메라 고정 ROI (x160:350,y105:315) 저채도 밝은 봉 외형 mask를
10개 참조와 IoU 비교. 위 근접 조건 AND IoU>=0.35 3프레임 지속시
2배: 2프레임. 유사도는 임시 영상 휴리스틱이며 검증된 봉/접촉 검출기 아님.
양쪽 노란 영역이 5프레임 미검출 AND 기록된 abs(yaw)>=0.1 AND
20프레임 안 재검출: 1.4배, 28프레임. 탐색 의도 정답은 아님.
한 카메라만 노란 영역 검출: 842프레임, 양쪽 미관측 탐색에 넣지 않음.
겹치는 조건은 최대값, 16-step chunk 평균. 카메라 attention 직접 변경 아님.
정적 사진을 action 시연으로 추가하지 않음. qpos/contact GT 입력 없음.
검토: 근접 후보 표본 review-0.jpg 및 봉/탐색 후보 전체 rod-search-review.jpg.

검사:
실제 U0 loader 3,810개 chunk, split disjoint, manifest/parquet SHA 검증 통과.
샘플러 가중 1~1.9625, 가중 chunk 3,141개, 선택확률 약85.44%.
기존 weighted_sampling/visual_importance 테스트 11개 통과.
새 실험 스크립트 Python/shell 구문 검사 통과.

실행 상태는 progress.json / launch.json / train.log가 기준.
run.py는 중복 launch 차단 및 오류 기록. 학습 종료 후 별도 eval 로그/JSON 기록.
기존 첫 학습 progress.json은 덮어쓰지 않음.
정적 걸림 외형과 실제 동적 끼움/분리 성공은 구분해야 함.

수정 및 중단 기록 (이 항목이 위의 최초 실행 계획보다 우선함)
- 첫 실행은 optimizer step의 foreach AdamW 임시 GPU 할당에서 OOM.
  새 체크포인트 저장 없음. 기존 모델은 변경 없음.
- 사용자 지시로 화면 잘림에 따른 valid=False 조건 삭제.
  해당 회귀 테스트가 수정 전 실패/수정 후 통과함을 확인. 관련 11개 테스트 통과.
- 사용자가 기존 색상/크기/중앙/지속 프레임 조건을 질의하여 정확한 값을 설명.
- 최신 사용자 요구: 색상 외 타원형 부표 외형을 함께 인식. 중앙은 접근 보조일 뿐.
  근접 판정은 학습 기반으로 변경. 사진을 사용하여 끼움 상태도 인식해야 함.
- 사용자 추가 확인: 손 정렬 때 '좌측'은 전방 영상의 부표 위치를 뜻함.
- 기존 참조는 우측 포크, front=stereo_left, robot-relative buoy y=-0.095/-0.14m.
  scene front image-right axis=(0,-1,0), 실제 참조 부표는 우측 가장자리.
  사용자 좌측 요구와 참조가 충돌. 임의 영상 뒤집기/명령 반전/카메라 변경 안 함.
- 이전 임의 조건 준비 스크립트와 실행 경로 차단. 원본 실패 자료는
  superseded_heuristic_attempt/에 보존. 아직 학습 기반 판정기로 교체 완료한 것은 아님.
- perception_evidence.jsonl: 기존 train/validation 분리 유지, RGB 5461쌍과
  staged 참조10쌍 색인. 접근/작업 단계 및 동적 끼움 정답은 없으므로 null 유지.
  참조10쌍은 staged_seated_geometry 외형 증거만 부여, dynamic_retention=null.
  기존 에피소드 success를 프레임별 성공으로 복제하거나 휴리스틱을 정답으로 쓰지 않음.
- learning_requirements.json 및 진행 HTML에 최신 요구·정답 부재·방향 충돌 표시.
- 현재 추가10000 학습은 재시작하지 않음. 모델 학습/검증 완료로 보고하지 않을 것.
- train_low_memory.py는 foreach=False AdamW 실행을 준비한 파일로, CPU 소형
  파라미터에서 foreach/serial 5-step 비교 통과. 실제 GPU 재학습 검증은 아직 없음.

최종 사용자 정정 후 재시도 (앞선 중단 기록보다 우선)
- 우측 끼움의 전방 우측 영상은 정상. 가능한 전방 좌측을 선호하되 우측도
  동등하게 취급한다고 사용자 확인. 방향 충돌은 해소됨.
- 재녹음은 하지 않음. 기존 정렬/작업 영상 검토37 episode 구간을 2배,
  나머지 1배로 학습하는 revised run을 실행함.
- prepare_reviewed.py: 기존 coarse visual review annotation만 재사용.
  모든 픽셀 기반 HSV/중앙/면적/연속검출/ROI유사도/탐색 임계값은 샘플링 미사용.
- train/은 원본 data/videos/meta를 참조하는 격리된 dataset view.
  meta/tasks.jsonl만 새로 작성: 노란 타원형 부표, 접근 중앙 보조,
  손카메라 봉-홈 정렬, 전방 좌측 선호, 우측 끼움 동등 허용을 언어 지시로 추가.
  원본 행동/원본 task metadata는 바꾸지 않음. 언어 지시 반영은 선호 행동
  성능 검증이나 새 판정기 구현 완료를 뜻하지 않음.
- 사진은 외형 검토 자료로 사용. action label 없는 정적 사진을 행동 시연으로
  편입하거나 dynamic_retention 성공 라벨로 변환하지 않음.
- 실제 로더 재검사: 3810 chunk, 1375 강조, 1~2배,
  강조 구간 추출 확률48.43%, train/val session 분리 및 원본 해시 검증 통과.
- 실패한 첫 실행 launch/model/log는 superseded_heuristic_attempt/에 보존.
- train_low_memory.py의 AdamW foreach=False와 expandable_segments 적용.
  동일 base weight2/checkpoint40000에서 새 optimizer/scheduler로 10000 재시도.
- run.py가 학습 종료 후 checkpoint5000/10000 저장계약 및 기존 validation
  40관측 MSE를 평가. 평가 과제 문장은 기존과 같으며 좌측 선호 평가가 아님.
- 최종 실제 실행 상태는 최신 progress.json/train.log 기준으로 확인.
