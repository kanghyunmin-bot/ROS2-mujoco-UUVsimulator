1. 기본 환경과 부표

Research pool · distributed physics와 April Real2Sim 물리를 기본으로 유지했다.
일반 GUI에는 연구 수조를 표시하고 다른 환경은 고급·비교 선택에 모았다.
기존 환경 파일과 CLI 선택지는 삭제하지 않았다.
연구 수조 장면의 부표를 3개에서 노란색 1개로 줄였다.
접근→정렬→분리를 한 episode로 수집하는 실험 구성을 문서화했다.
자동 무작위 초기화나 자동 성공 판정을 구현한 것은 아니다.

2. 센서 오차 모드

물리/광학 설정과 독립적인 오차 모드 선택을 추가했다.
선택지: 기존 센서 설정(기본), 수학적 오차·가정값, 4월 bag 압력 부분 보정(2 Hz).
'기존 센서 설정'은 무오차가 아니라 기존 수학 모델과 override를 유지한다는 뜻이다.
수학적 모델을 새로 중복 구현하지 않고 기존 IMU/Bar30/A50 구현을 재사용했다.
IMU bias, Gauss–Markov, random walk, 백색잡음, 압력 drift 및 DVL 측정속도
적분에 따른 누적오차 등의 기존 경로를 선택·검증했다.
명명된 모드는 충돌하는 센서 override를 정리하고 프로필과 seed를 적용한다.
실행 중 변경은 막고 다음 시작 시 적용한다. 재시작 때 선택을 유지한다.
프로필 내용, SHA-256, 제거·적용된 override를 실행 증거로 남긴다.

bag 근거의 범위:
  압력 변동과 당시 2 Hz 출력 주기만 부분 보정.
  IMU/DVL 장기 drift 및 지연 전체가 실측 보정되었다고 주장하지 않는다.
  임의의 작업 단계별 시간 구조를 novelty로 추가하지 않았다.

3. 녹화 기본값과 사전 점검

기본 센서 카메라를 4 Hz에서 VLA lite 640×360, 15 Hz로 변경했다.
저장 관측/행동 주기는 기존 10 Hz를 유지한다. 미리보기 FPS는 별개다.
녹화 준비 시 PWM span=400, FFmpeg 사용 가능 여부, 알려진 저주기 수심
설정을 확인한다. bag 2 Hz를 임의 보간하여 10 Hz 정상 데이터로 만들지 않는다.
15 Hz 설정만으로 실제 처리량이 보장되지는 않으므로 첫 시연 실측이 남아 있다.

7. 실제 시작 버튼 오류 후속 수정

증상: Start 클릭 후 sim: stopped 유지. 시뮬 프로세스는 생성되지 않음.
실행 중 GUI 로그에서 sensor_error_mode unexpected keyword TypeError 확인.
원인: HTTP 요청/프로세스 관리자는 새 인자를 처리하지만 중간
WebGuiController.start_sim_stack 전달 함수에서 인자가 누락되었다.
수정: 선택한 sensor_error_mode를 중간 함수에서 받아 프로세스 관리자에 전달.
검사: HTTP 명령 처리 -> 실제 controller -> 프로세스 관리 호출 경로를 추가.
수정 전 같은 TypeError 재현, 수정 후 관련 검사 35개 통과.
기존 테스트의 controller mock이 실제 함수 시그니처 누락을 가렸던 한계를 보완했다.
적용: 실행 중인 GUI 서버를 재시작해야 새 Python 함수가 로드된다.
이 후속 검사는 실제 SITL/MuJoCo 전체 기동 성공 검증을 대신하지 않는다.

8. 중립 조이스틱에서 RC가 해제되는 문제

사용 중 로그에서 web RC watchdog released stale input 반복을 확인했다.
기존 브라우저 keepalive가 스틱 움직임이 있을 때만 전송되어 중앙 복귀 후
0.4초가 지나면 서버가 연결 상실로 판단하는 코드 경로를 확인했다.
Pilot input이 활성인 동안 중립 명령도 계속 갱신하도록 수정했다.
수동 입력 해제/페이지 숨김/장치 해제 경로와 서버 watchdog 시간은 유지했다.
중립 keepalive 회귀 검사가 수정 전 실패하고 수정 후 통과했다.
관련 JavaScript 검사 4개, 구문 및 diff 공백 검사 통과.
브라우저 새로고침 후 적용된다. 실제 무선 장치 및 브라우저 부하로 인한
다른 입력 단절까지 해결되었다고 단정하지 않는다.

9. 카메라와 VLA 수집 동시 표시

studio.js / studio.css에서 수집 창을 좌측 전방·손 영상, 우측 레코더 및
조종 패널의 통합 배치로 변경했다. 카메라 설정은 수집 창에서 기본 접힘이다.
기존 영상/조종 DOM을 이동하므로 스트림이나 컨트롤 ID를 복제하지 않는다.
창을 닫으면 영상과 조종 패널이 원래 위치로 돌아간다. 작은 화면은 세로 배치다.
실제 웹 GUI에서 두 영상과 저장 버튼 동시 표시, 닫기 후 원위치 복원을 확인했다.
JS 구문 및 diff 공백 검사 통과. 운용 중 녹화/Arm/RC 명령은 테스트하지 않았다.

10. 프로콘 / 다중 조종기 선택

호스트에서 기존 SHANWAN USB 수신기와 Bluetooth Pro Controller 연결을 확인했다.
프로콘 kernel 로그에 subcommand 재시도 한도 및 IMU report 누락이 관측되었다.
이 로그만으로 스틱 보고 단절의 원인을 단정하지 않는다.
GUI에 명시적인 조종기 선택 목록을 추가했다. 두 개 이상 연결 시 첫 장치를
임의 선택하지 않으며 선택한 장치가 끊겨도 다른 장치로 자동 전환하지 않는다.
장치 선택 변경 시 기존 입력을 해제한다. 단일 장치 최초 연결은 자동 선택한다.
다중 장치 선택/해제 검사와 기존 RC 요청/중립 keepalive 검사 통과.

11. USB 프로콘 방향별 범위 보정

사용자가 두 스틱을 끝까지 한 바퀴씩 돌린 구간임을 확인하고 측정값 적용을 요청했다.
Linux EV_ABS X/Y/RX/RY를 32767로 정규화한 최소/최대:
  왼쪽 X: -0.913144322031312 / +0.93465987121189
  왼쪽 Y: -0.8170415356913968 / +0.9503769035920285
  오른쪽 X: -0.8948942533646657 / +0.836787011322367
  오른쪽 Y: -0.7967162083803827 / +0.8607745597705008
app.js에서 각 방향의 끝값이 ±1이 되도록 구간별 선형 보정하고 초과값을 제한한다.
중앙은 새로 측정하지 않았으므로 0과 기존 원시 입력 deadzone 0.10을 유지한다.
보정식: sign(x) * (abs(x)-0.10)/(해당 방향 측정 끝값의 절댓값-0.10).
Nintendo Pro Controller 이름 또는 VID:PID 057e:2009인 장치에 적용한다.
브라우저 표준 스틱 순서 0/1/2/3을 사용하며 장치 고유 일련번호 구분은 없다.
이 PC의 한 프로콘 실측 프로필이며 다른 프로콘이나 Bluetooth 범위의 보편값이 아니다.
GUI에 '프로콘 범위 보정' 표시. 새로고침 후 반영된다.
끝값 회귀 검사는 수정 전 실패, 수정 후 통과. 중립 유지/초과 제한/다른 패드
기존 범위 유지 및 RC/오차 모드 검사를 포함해 JavaScript 8개 통과.
기존 녹화 파일은 변경하지 않는다. 녹화에는 기존과 같이 보정 후 RC 명령이 저장된다.

12. 분리 지시문 기본값 및 세션별 무작위 표현

recorder.js의 '부표 앞 정지' 기본값을 노란 부표 접근·포크 정렬·분리 표현
3종으로 교체했다. 화면 최초 로드 및 세션 종료 후 다음 세션 초안에서 무작위
선택하며 직전 문장 반복을 피한다. 직접 편집도 세션 준비 전에 가능하다.
현재 서버는 세션 준비 시 지시문을 고정하므로 같은 세션의 episode들은 같은
문장을 유지한다. 녹화 도중이나 상태 polling 때 무작위로 변경하지 않는다.
새로고침 후 실행 중 레코더의 실제 task를 표시해 임의 초안과 기록 불일치를 막는다.
JS 구문 및 diff 공백 검사 통과. 기존 저장 자료는 변경하지 않는다.

13. 시연 녹화 시간 진행률

수집 창에 목표 시뮬 시간(기본 30초, 5~600초 조절), 0~100% 진행 막대,
경과/목표 시간과 남은 시간을 추가했다. 실제 recorder duration_s를 사용하며
wall time으로 임의 진행시키지 않는다. 상태 단절 시 마지막 확인값임을 표시한다.
100%는 시간 분량 목표일 뿐 임무 성공/데이터셋 충분도가 아니다.
자동 정지하지 않으며 분리 성공 시 목표 전에 저장할 수 있다.
저장 후에는 10 Hz 프레임 수로 추정한 최근 저장 길이를 표시한다.
새 episode 시작 시 초기화, 폐기 시 제거. 녹화 중 목표 편집은 잠근다.
진행률/저장 후 표시 및 초기화/수신 단절 검사 3개와 JS 구문 검사 통과.

14. 저장된 시연 누적 개수

수집 창 상단에 전체 저장 수, 분리 성공/실패, 기타·테스트 개수를 추가했다.
분리 성공 50개를 첫 수집 목표로 표시하고 진행률과 남은 개수를 보여준다.
50개는 학습 성능을 보장하는 기준이 아니다. 성공 여부는 저장 라벨 기준이며
영상 검수 전임을 명시한다. 기본 분리 지시문 3종의 simulation task_demonstration만
분리 임무로 집계하며 다른 지시문·접근 정지 테스트는 기타로 분류한다.
모든 세션의 완료된 episode manifest를 읽고 3초간 캐시한다. 이미지와 샘플은
읽지 않으며 녹화 중 자료는 포함하지 않는다. 손상된 manifest는 오류 수로 표시한다.
백엔드 변경이므로 세션 저장·종료 후 GUI 서버 재실행과 브라우저 강력 새로고침 필요.

15. 세션을 유지하는 다음 시연 초기화

수집 창에 '다음 시연 초기화' 버튼을 추가했다. 이 GUI 소유의 최신 레코더 상태가
대기 중일 때만 허용하며 녹화·저장 요청 처리 중에는 거절한다. STABILIZE/MANUAL
수집을 지원한다. ALT_HOLD는 기존 수심 목표 문제로 지원하지 않는다.
조종 입력을 해제하고 서버에서도 신규/대기 RC 입력을 차단한다. ROS Trigger 서비스
/uuv_mujoco/demo_reset는 요청을 큐에 넣고, 실제 MuJoCo 상태 변경은 물리 스레드가
수행한다. 완료 응답까지 다음 녹화와 추가 초기화를 막는다.
시작 시 저장한 qpos, equality 활성/상대 자세, 충돌 비트와 부표 표시를 복원한다.
부표 분리·포획·접촉 이력, 속도·잔여 힘·추진기 상태와 차분 가속도 이력을 정리한다.
시뮬 시간은 되돌리지 않고 2초간 자세를 고정해 센서 값을 갱신한다. 센서 노이즈
난수·드리프트 및 기존 세션은 유지한다. SITL은 잠시 MANUAL로 전환한 뒤 원래
모드의 실제 수신 확인과 추가 0.5초를 기다린다. ARM/DISARM 명령을 보내지 않는다.
모드·연결·ARM 확인 실패나 제한 시간 초과는 실패로 표시하며 자동 재시도하지 않는다.
초기화 완료 후 조종 입력을 켜고 녹화를 시작한다. 기본 위치로 복귀하며 무작위화는 없다.
물리 폭주로 프로세스가 종료된 경우 자동 재시작하는 기능은 포함하지 않는다.
기존 폭주 감지/진단 보존은 유지하며, 실패한 시연을 정상 시연으로 이어 붙이지 않는다.
최초 반영 시 GUI와 MuJoCo 재실행 및 브라우저 강력 새로고침이 한 번 필요하다.
실제 research pool 모델의 재부착/재분리 상태 초기화·반복 초기화·단조 시계,
독립 ROS domain 서비스 응답, 모드 확인·시간 초과 및 녹화 보호 검사를 추가했다.
실행 중인 사용자 시뮬/녹화에는 초기화 명령을 보내지 않았다. 실제 운영 SITL에서
버튼을 누르는 최종 사용 확인은 적용 후 필요하다.
